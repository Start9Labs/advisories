# A service configured to use a specific outbound gateway can silently use the system default instead

## Symptom

A service set to route its outbound traffic through a specific gateway (not the system-wide default) sometimes has that setting ignored — its traffic goes out over the system's pinned default gateway instead. There is no error; the service just behaves as if its own outbound gateway setting were never applied, and any check that only looks at the service's configured gateway (rather than watching its actual traffic) shows nothing wrong.

## Affects

Servers with more than one outbound gateway available, where a system-wide default gateway is pinned and at least one service is separately configured to use a different outbound gateway. Servers with only one gateway, or no pinned system-wide default, are not affected.

## Cause

The pinned system-wide gateway installed a rule that matched before the kernel reached the service's own outbound rule, so the system default won regardless of the service's setting. The service override also only existed in the IPv4 rule table, leaving IPv6 traffic on the system route.

## Remedy

Update to StartOS 0.4.0.2 when it is available, which reorders the rule priorities so a service's outbound gateway override takes effect before the system-wide default, and applies the override to both IPv4 and IPv6.

## Notes

Fix is merged and unreleased at time of writing; StartOS 0.4.0.2 is next. The maintainer's PR notes this has not yet been exercised on a real two-gateway device, so treat reports of continued misrouting after updating to 0.4.0.2 as worth escalating rather than closing out.
