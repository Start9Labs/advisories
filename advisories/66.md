# vLLM: `/v1/models` returns `500 Internal Server Error` with `AttributeError: '_IncludedRouter' object has no attribute 'path'`

## Symptom

Calling the OpenAI-compatible `/v1/models` endpoint fails with a `500 Internal Server Error`. The server log shows:

```
AttributeError: '_IncludedRouter' object has no attribute 'path'
```

raised from inside `prometheus_fastapi_instrumentator`'s route-resolution middleware (`routing.py`, `route_name = route.path`). The vLLM server itself starts normally; only requests through the instrumentation middleware — including `/v1/models` — fail.

## Affects

Deployments running vLLM with a `fastapi` version that changed the internal router type used by prometheus_fastapi_instrumentator's route matching. Any endpoint the instrumentator wraps can be affected, not only `/v1/models`.

## Cause

An incompatibility between `prometheus_fastapi_instrumentator` and newer `fastapi` releases (0.137 and later), where `fastapi`'s internal route object no longer exposes `.path` the way the instrumentator expects.

## Remedy

Pin `fastapi` to a version older than 0.137. vLLM maintainers have said they will patch the PyPI wheels to pin `fastapi < 0.137`; until an updated build is installed, downgrade the `fastapi` package in the vLLM environment to below 0.137.

## Notes

Reported as a duplicate of vllm-project/vllm#45596. No fixed vLLM version has been named yet by maintainers — only the plan to pin fastapi in the wheels — so do not promise a specific vLLM release number.
