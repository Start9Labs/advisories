# Raspberry Pi 4: WiFi never comes up, `wlan0` missing — firmware missing from the image

## Symptom

On a Raspberry Pi 4 running StartOS 0.4.0.1, WiFi does not work at all: `wlan0` never appears, and `nmcli radio` reports `WIFI-HW: missing`. `dmesg | grep brcmfmac` shows the driver finding the chip but failing to load firmware:

```
brcmfmac: brcmf_fw_alloc_request: using brcm/brcmfmac43455-sdio for chip BCM4345/6
brcmfmac mmc1:0001:1: Direct firmware load for brcm/brcmfmac43455-sdio.raspberrypi,4-model-b.bin failed with error -2
brcmfmac mmc1:0001:1: Direct firmware load for brcm/brcmfmac43455-sdio.bin failed with error -2
brcmfmac: brcmf_sdio_htclk: HT Avail timeout (1000000): clkctl 0x50
```

## Affects

Raspberry Pi 4 servers on the current Pi image (0.4.0.1). Servers connected by Ethernet are unaffected in practice, since only WiFi is broken. Other Pi models and non-Pi hardware are not affected.

## Cause

A regression from #3089, which moved the firmware package list in `generate.sh` behind a nonfree check that does not match `raspberrypi`, dropping `firmware-brcm80211` from the Pi image.

## Remedy

This is fixed for the next StartOS release; 0.4.0.2 restores `firmware-brcm80211` to the Pi image. Until then, a Pi 4 that needs WiFi should be connected by Ethernet, or reflashed once 0.4.0.2 is available.

## Notes

- The reporter's manual firmware-copy workaround requires downloading a `.deb` and writing into the writable overlay over SSH; it is not something to walk a customer through, since it needs tools and paths the StartOS UI does not expose.
- A separate, unconfirmed problem was found while investigating this: on at least one device the btrfs filesystem backing `/media/startos/config` had not been grown to fill its partition, leaving very little free space. That has been filed separately as #4009 and is not part of this advisory.
