# Immich mobile app: video plays with an endless spinner instead of falling back to the server copy

## Symptom

Opening a video in the Immich mobile app on iOS shows a spinner that never resolves, even though the same video plays fine in the web browser. The app's log shows `No file found for the video`. This happens for videos that are backed up to the server but whose local copy on the phone can no longer be read — for example, an iCloud-optimized original that has been offloaded and fails to download at that moment.

## Affects

iOS users of the mobile app viewing a video whose local file is missing or unreadable (commonly triggered by "Optimize iPhone Storage" with low free space, after the device has offloaded the original to iCloud) while the video is already backed up to the server. Does not affect videos viewed through the web UI.

## Cause

The mobile video viewer prefers the local copy of a video and throws an error when that local file cannot be read, without falling back to the server copy that is available a few lines later in the same code path.

## Remedy

This is a known bug, fixed upstream, with the fix not yet in a released version of the mobile app. Once it reaches a release, the viewer will log a warning and play the server copy (original or transcoded, per the existing transcoding setting) instead of spinning forever. There is no remedy to apply yet; affected users can view the video from the Web Vault in a browser in the meantime.

## Notes

- Still open as unresolved by this fix: the same fallback for images (which currently just show a broken icon), and any visible indication to the user that a server fetch is happening instead of a local playback — both called out by maintainers as follow-up work, not part of this fix.
- A related crash where the player itself throws an error (rather than the file being unreadable) is tracked separately upstream (issue #25421) and is not covered by this fix.
