# Immich: tags applied to assets return no results when searching by tag — fixed in 3.2.0

## Symptom

An asset shows a tag applied to it (visible in the asset's tag list), but searching or browsing by that tag returns no assets. This can affect tags created via the API as well as tags created normally, especially tags organized in a hierarchy (e.g. `parent/child`).

## Affects

Immich versions before 3.2.0, particularly libraries using hierarchical (nested) tags. Not everyone using tags hits this — only tags whose parent linkage became broken.

## Cause

A hierarchical tag's `parentId` could end up missing or unset even though the tag's `value` still encoded a parent path (e.g. `autotagged/error-missing-path`). The search query relied on the parent relationship, so tags with a broken parent link were applied to assets correctly but excluded from tag search results.

## Remedy

Update to Immich 3.2.0 or later, which fixes the tag/search parent-linkage bug.

## Notes

As of this writing there is no documented migration step to automatically repair tags that were created with broken parent links before upgrading; assets already mistagged this way may still need their tags reapplied after updating. If a customer reports this on an older version, the recommendation is to update first and confirm whether the specific tags are searchable afterward.
