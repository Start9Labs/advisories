# Immich mobile app: "Sync failed. Cannot process backup" loops forever on Live Photo videos

## Symptom

The mobile app repeatedly shows "Sync failed. Cannot process backup." Recently-taken photos show as "not backed up" in the app even though they already appear in the web UI. Server-side Postgres logs show repeated errors like:

```
ERROR:  duplicate key value violates unique constraint "UQ_assets_owner_checksum"
DETAIL:  Key ("ownerId", checksum)=(<ownerId>, \x<checksum>) already exists.
```

Restarting the server container temporarily clears the error, but it returns.

## Affects

Users backing up from the iOS mobile app whose library contains Live Photos. The stuck assets are consistently the hidden `VIDEO` component of a Live Photo that is already stored server-side and linked to its still — the app's sync stream never returns hidden assets, so it retries them indefinitely. Not a StartOS-specific packaging issue; reported against server v3.1.0 on both Docker/TrueNAS and Raspberry Pi installs.

## Cause

Not yet confirmed by Immich maintainers. One reporter traces it to hidden Live Photo video assets that are excluded from the sync stream, causing the mobile app's local sync state to never converge; a second reset can broaden the retry set to include the linked stills. The `duplicate key value violates unique constraint "UQ_assets_owner_checksum"` message is a red herring — it appears during normal duplicate handling too, not just when the loop is stuck.

## Remedy

No fix has shipped yet. In the app, clear the cache and use "Reset SQLite Database" — this resolved it for at least one reporter without needing to reinstall. If that does not clear the loop, a full app deletion and reinstall has resolved it for others. Immich maintainers are still asking affected users for mobile app logs at the time of the failure to pin down the cause.

## Do not

- Don't treat the Postgres `duplicate key value` log line alone as confirmation of this bug — it fires during ordinary duplicate-upload handling as well.
- Don't assume it's a network or server-reachability problem — reporters confirmed the server and web UI stayed reachable throughout.

## Notes

Reported across multiple independent servers and accounts, including two iOS devices on the same account and two separate accounts on one server, ruling out a device-specific cause. Maintainers have not yet confirmed root cause or a fix version as of the last update (2026-09-17).
