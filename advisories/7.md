# Bitwarden extension opens blank or the vault shows empty against Vaultwarden older than 1.37.2 — update Vaultwarden first

## Symptom

The Bitwarden browser extension opens blank or sits on a loading skeleton; the vault shows zero items; unlock fails with `no elements in sequence` or `Invalid time value`; a correct 2FA code is rejected; Lock and Log out are greyed out. On mobile and desktop the client signs in and reports a successful sync but the vault appears empty, while new items can still be added. The Web Vault in a normal browser tab works fine and still shows everything, which is what makes it look like a client-side problem.

## Affects

Official Bitwarden clients released from 24 July 2026 onward — browser extension, desktop, Android, iOS and CLI — against Vaultwarden older than 1.37.2. A user reporting it on one client is hitting it on all of them. The browser extension from 2026.8.0 breaks hardest, for any account in an organization that has a policy defined, even a disabled one.

## Cause

Two client-side changes. Clients from 24 July are stricter about the JSON the server returns, and older Vaultwarden builds send data they reject. Browser extensions 2026.8.0 and newer also require a `revisionDate` field on organization policies, which Vaultwarden 1.37.1 and older omit, so the extension crashes; that bad policy is cached in the extension's local storage and read at login before any sync, so updating the server alone does **not** revive an extension that has already broken — the cached copy has to be replaced.

## Remedy

**Step 1 — Update Vaultwarden to 1.37.2 or newer.** Do this first; step 2 fails against an older server and has to be redone. Confirm it took on the **Admin Portal** interface: sign in with the admin token and check the diagnostics page reads 1.37.2 or newer. Mobile, desktop and CLI clients need nothing more.

**Step 2 — Give the browser extension a clean copy of the policy.**

**Firefox — downgrade, sync, upgrade.** Done in place, so your extension settings survive.

1. `about:addons` → gear icon → untick **Update Add-ons Automatically**.
2. Open the [version archive](https://addons.mozilla.org/en-US/firefox/addon/bitwarden-password-manager/versions/) and **Download file** for **2026.7.0**.
3. `about:addons` → gear icon → **Install Add-on From File** → choose the downloaded `.xpi`.
4. Open the extension, log in with your server URL, email and master password, then **Settings** (bottom bar) → **Vault options** → **Sync vault now**.
5. Gear icon → re-tick **Update Add-ons Automatically** → **Check for Updates**.

**Chrome / Brave / Edge / Opera — remove and reinstall.** These stores don't serve old versions, so there's no in-place downgrade; reinstalling drops the same cached policy in one step.

1. `chrome://extensions` (Edge: `edge://extensions`, Opera: `opera://extensions`) → **Bitwarden Password Manager** → **Remove** → confirm.
2. Quit the browser completely and reopen it.
3. Reinstall: [Chrome Web Store](https://chromewebstore.google.com/detail/bitwarden-password-manage/nngceckbapebfimnlniiiahkandclblb) (also for Brave and Opera) · [Edge Add-ons](https://microsoftedge.microsoft.com/addons/detail/bitwarden-password-manage/jbkfoedolllekgbhcbcoahefnbanhhlh).
4. Enter your self-hosted server URL, log in, then **Settings → Vault options → Sync vault now**.

**Safari** — the extension ships inside the Mac App Store desktop app and can't be downgraded or cleared independently. Use the Web Vault at your server URL in a normal tab until a fixed client reaches the App Store.

If you specifically want the older build rather than a reinstall, every browser's 2026.7.0 package is on the [Bitwarden release page](https://github.com/bitwarden/clients/releases/tag/browser-v2026.7.0) — note that on Chromium browsers these load as an unpacked developer extension with its own separate storage, so they don't fix the store-installed copy.

## Do not

Do not suggest deleting the account or the vault on the client side; no client-side account deletion is ever part of the fix. Vault data is never at risk — it stays intact on the server throughout.
