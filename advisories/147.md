# Open WebUI: Attach Webpage fails with 403 Forbidden on Wikipedia and similar sites even with USER_AGENT set

## Symptom

Attaching a webpage (Attach Webpage) fails with `403 Forbidden` on sites that reject the default aiohttp user agent — Wikipedia among them — even though `USER_AGENT` has been configured. The attachment fails before the page is ever fetched for its content.

## Affects

Anyone using Attach Webpage against a site that blocks the default aiohttp user agent, regardless of whether `USER_AGENT` is set — the pre-check that decides whether the URL is a page or a file ignored that setting. Direct file URLs (e.g. PDFs) are unaffected.

## Cause

The web loader itself sends the configured `USER_AGENT`, but a separate pre-check request — used to decide whether the URL points to a webpage or a file — ran first and did not send it, so the request could be rejected before the loader was ever reached.

## Remedy

This is fixed upstream, but the fix has not yet reached a released version of Open WebUI on StartOS — there is no version to update to yet. Once a release containing it is available, `USER_AGENT` set to a value accepted by the target site (e.g. a normal browser user agent) will let Attach Webpage succeed on sites like Wikipedia that reject the default aiohttp user agent.

## Notes

Fix merged upstream (open-webui/open-webui#30385) but not yet in any released Open WebUI version — no release has been made since the merge.
