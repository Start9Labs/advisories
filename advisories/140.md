# Open WebUI: editing a shared knowledge base file as a collaborator shows "updated" but the old text stays

## Symptom

A user with write access to a shared knowledge base edits one of its files (for example a `.txt` file) and sees the green "updated" success message. But reopening the file shows the old text is still there — the edit was not actually saved — and a chat using the knowledge base keeps answering from the old content, not the edited one.

## Affects

Anyone editing a file in a knowledge base they have write access to but do not own (shared by another user, e.g. an admin). Editing a file in a knowledge base you own is unaffected.

## Cause

The endpoint that saves the edit correctly allows the file's owner, an admin, or a user with write access. But the step that actually rewrites the file and its search index only recognized the file's owner or an admin — for anyone else it failed silently, was logged as an exception on the server, and the endpoint still reported success to the user.

## Remedy

This is fixed upstream, but the fix has not shipped in any released version yet — there is no release naming it yet. Until it is available, a collaborator's edits to a shared knowledge base file are not saved even though the interface says they are; the file owner or an admin should make the edit instead.

## Do not

- Do not tell the user to re-save or retry the edit — the same silent failure will recur regardless of version, until the fix ships.

## Notes

Fix merged upstream (open-webui/open-webui#30448) but not yet in any released Open WebUI version; update this advisory once a release names it.
