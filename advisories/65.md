# Gitea: update to 1.26.3 for additional security fixes — org label leaks, fork sync after parent goes private, reverse-proxy impersonation, TOTP replay, and push permission escalation

## Symptom

No visible symptom for most users. These are security issues discovered and fixed rather than something a user would notice in normal operation: private organization labels could be read through label endpoints by non-members, forked repositories could keep pulling commits via "merge-upstream" after the parent repository was made private, the Docker `app.ini` templates defaulted `REVERSE_PROXY_LIMIT`/`REVERSE_PROXY_TRUSTED_PROXIES` to `= *`, which allowed `X-WEBAUTH-USER` header impersonation if reverse-proxy auth was enabled, TOTP one-time passcodes could be replayed due to a race condition across web login, password reset, and Basic-Auth, and a per-branch "maintainer can edit" grant could escalate to full repository write access because permission was only checked once per push instead of once per ref.

## Affects

All Gitea installations on versions prior to 1.26.3.

## Remedy

Update to Gitea 1.26.3, which contains these fixes along with the other 1.26.3 security fixes (see the separate advisory on the RSS/Atom feed, migration SSRF, and notification API issues).

## Notes

Reverse-proxy authentication (`X-WEBAUTH-USER`) is now opt-in and must be explicitly configured by an admin; installations relying on reverse-proxy auth should confirm their configuration still works after updating.
