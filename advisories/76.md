# StartTunnel installer piped to `sh` as a non-root user installs nothing, exits 0 — download the script first instead

## Symptom

Running the documented install command as a regular (non-root) user —

```
curl -sSL https://start9.com/start-tunnel/install.sh | sh
```

— prints `Root privileges required. Re-running with sudo.`, then stops. It exits with status 0 and prints no error, but nothing is installed: `dpkg -l start-tunnel` reports no package found. Running the same command with `| bash` gives the same result.

## Affects

Anyone installing StartTunnel on a fresh host by piping the installer directly to a shell (`curl ... | sh` or `curl ... | bash`) while logged in as a non-root user with sudo rights — the exact command in Start9's own install instructions. Running the installer as root directly, or downloading it to a file first, is not affected.

## Cause

The installer re-execs itself under `sudo` by copying the piped script from its own stdin, but by the time it does so the shell has already consumed the piped input, so the copy it hands to `sudo` is empty. The empty script runs and exits 0, giving no indication anything went wrong.

## Remedy

Do not pipe the installer directly to a shell as a non-root user. Instead, download it to a file first, then run that file:

```
curl -fsSLo install.sh https://start9.com/start-tunnel/install.sh
sh install.sh
```

This path is not affected by the bug and completes the install normally. Alternatively, run the piped install command as root rather than a sudo-capable user.

## Do not

- Don't re-run the same piped command expecting a transient failure — it will exit 0 and appear to succeed every time on an affected setup.
- Don't assume the install failed for an unrelated reason (network, package repo) — `dpkg -l start-tunnel` showing nothing after a clean, no-error run is the signature of this bug specifically.

## Notes

Reported against a fresh Debian 13 host installing StartTunnel 1.3.0 via the installer at `start9.com/start-tunnel/install.sh`; the bug is in that installer script, not in StartTunnel itself or in StartOS. No fix has merged yet as of this report.
