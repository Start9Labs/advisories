# Electrs 0.12 needs Bitcoin Core 31.1:17 or later — Bitcoin Knots (pre-RDTS) and older Core lines show Bitcoin as "Incorrect version"

## Symptom

After updating Electrs to 0.12.0:0, or installing it fresh, its service page lists Bitcoin under Dependencies as **Incorrect version**: Electrs requires Bitcoin `>=31.1:17`, and the installed Bitcoin is Bitcoin Knots (pre-RDTS) `29.3:27`, or Bitcoin Core 28.4, 29.4 or 30.3. Started anyway, Electrs never indexes. The same Bitcoin was fine with Electrs 0.11.1:20. Users on Bitcoin Knots ask whether Knots is still supported, or why the Community Registry offers no newer Knots to update to.

## Affects

Anyone whose Bitcoin is not Bitcoin Core 31.1:17 or later once Electrs is on 0.12.0:0 or later:

- **Bitcoin Knots (pre-RDTS)** from the Community Registry. Its latest is 29.3:27, and no newer Knots (pre-RDTS) is coming, so no Knots will ever satisfy Electrs 0.12.
- **Bitcoin Core 28.x, 29.x or 30.x** at any revision.

Not affected: Bitcoin Core 31.1:17 or later; Electrs still on 0.11.1:20; Fulcrum, whichever Bitcoin it runs against.

## Cause

Electrs 0.12 reads blocks over Bitcoin's REST interface, which only Bitcoin Core 31.1:17 and later serve, on a bridge-only binding added in that revision. Electrs 0.11 read blocks over p2p and accepted Bitcoin Core 28.4:17+, 29.4:4+, 30.3:4+ and 31.1:4+, and Bitcoin Knots (pre-RDTS) through its declared equivalence to Core 28.4 and 29.4. Knots (pre-RDTS) has no such binding and no release that will add one. The dependency error is correct; nothing is broken.

## Remedy

**On Bitcoin Core 28.x, 29.x or 30.x** — update Bitcoin to Bitcoin Core 31.1:17 or later, which is what the Marketplace offers by default, then update Electrs. The 0.12 update rebuilds the index: hours, and at least 120 GB free.

**On Bitcoin Knots (pre-RDTS)** — updating Knots is not an option. Three choices, in order of recommendation:

1. **Run Fulcrum instead of Electrs** (recommended). Fulcrum 2.1.2 accepts Bitcoin Knots (pre-RDTS) 29.3:27. It needs Bitcoin unpruned with `txindex` and ZeroMQ on — it raises that as a task on Bitcoin's page — and builds its own index, which takes hours. Point wallets at Fulcrum's **Electrum (SSL)** address afterwards, then uninstall Electrs.
2. **Switch Bitcoin's flavor to Bitcoin Core 31.1:17 or later.** It is an in-place switch on the same chain data, with no resync; mempool policy settings are reset to Core's defaults. Electrs 0.12 then indexes.
3. **Stay on Electrs 0.11.1:20.** If Electrs has not been updated yet, do not update it; 0.11.1:20 remains on the Start9 Registry as an older version. If it is already on 0.12.0:0, there is no downgrade: uninstall Electrs and install 0.11.1:20 from the version list, which rebuilds the index from scratch. Electrs receives no further updates on that node.

## Do not

- **Do not tell them to update Bitcoin Knots.** 29.3:27 is its latest and, in all likelihood, its last; no Knots (pre-RDTS) will reach 31.1:17. The Bitcoin Knots on `start9.mempool.guide` is not an update either — it is a different chain (advisory 1).
- **Do not call it a bug or send them to file an issue.** The dependency floor is deliberate and the error is correct.
- **Do not suggest downgrading Electrs in place.** 0.12.0:0 cannot migrate down. The only way back is uninstall and reinstall 0.11.1:20, with a full reindex.
- **Do not suggest starting Electrs 0.12 anyway.** Without the REST interface it cannot read a block.

## Notes

- Tell the flavors apart from Bitcoin's own page, which names the installed flavor: Knots (pre-RDTS) reads `29.3:27`; Core reads `31.1:17` or later.
- The Community Registry does publish Bitcoin Knots (pre-RDTS) 29.3:27 for StartOS 0.4.0. A Knots user who sees no version dropdown is on its only version, not missing a 0.4.0 build.
- Fulcrum 2.1.2 accepts Bitcoin Core 28.4:17+, 29.4:4+, 30.3:4+ and 31.1:4+, and Knots (pre-RDTS) through them.
- Electrs 0.12.0:1 adds a **Bitcoin REST** health check that fails with this remedy in its message and keeps Electrs from starting until Bitcoin can serve it. Until it reaches the Start9 Registry, 0.12.0:0 shows only the dependency error.

Known since 2026-09-20.
