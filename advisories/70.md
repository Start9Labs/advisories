# Mempool: address lookups silently fail with indexer misconfigured — update to 3.3.1:24

## Symptom

Address and transaction lookups do not work, but both health checks stay green and nothing in the UI indicates a problem. The logs show a repeating connection failure:

```
ERR: Electrum error: {"reason":"wrong version number","code":"ERR_SSL_WRONG_VERSION_NUMBER"}
INFO: Disconnected from Electrum Server at 127.0.0.1:3306
[Warning] Aborted connection 578380 to db: 'unconnected' user: 'unauthenticated'
```

This happens because the indexer selection form appeared to already have Fulcrum chosen (it did not), so closing it without explicitly saving left no indexer configured — while the backend stayed set to `electrum` and defaulted to talking to the package's own MariaDB port instead of a real Electrum server.

## Affects

Anyone who installed or updated Mempool without explicitly selecting and saving an indexer in the setup form — including installs that updated into this version of the feature and were never prompted at all. Versions before 3.3.1:24.

## Cause

The indexer select had no real default but rendered as though Fulcrum were already chosen; the task that would force a choice only ran on fresh installs, not updates. With no indexer set, `MEMPOOL.BACKEND` stayed pinned to `electrum` and fell back to upstream's default `127.0.0.1:3306` with TLS — which is this package's own MariaDB, not an Electrum server.

## Remedy

Update to Mempool 3.3.1:24 or later. On update, a critical task will appear asking you to select an indexer (Fulcrum or none); the service will not fully start until it is resolved. Select and save your indexer choice to restore address lookups. No other repair is needed — the update itself corrects the misconfigured backend setting on next start.

## Notes

Both health checks report success throughout, so this does not look like an outage — it looks like the service is fine and lookups simply don't work. If you see the SSL/MariaDB error pattern above, this is the cause.
