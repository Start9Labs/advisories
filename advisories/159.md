# Open WebUI: renaming a folder to a name made only of spaces blanks it and makes it disappear from the sidebar

## Symptom

Renaming a folder (via Edit, in the sidebar or on the folder page) to a name made only of spaces shows "Folder updated successfully" — but the folder and its chats then disappear from the sidebar, including after reloading the page. Renaming it to a completely empty name is correctly refused with "Folder name cannot be empty.", which is what makes the spaces-only case look like it should also be rejected.

## Affects

Anyone who renames a folder to a name that is only spaces, or uses "create subfolder" with a spaces-only name. Names with ordinary text, including ones with leading or trailing spaces around real text, are unaffected — those are trimmed and saved normally.

## Cause

The rename and create-subfolder handlers checked whether the name was empty before trimming it, so a spaces-only name passed that check and was then trimmed to blank and saved that way.

## Remedy

A fix has merged upstream (open-webui/open-webui#31380) that trims the name before checking it, refusing spaces-only names the same way empty names are refused. It has not yet reached a released version; it will be available once a release containing it reaches StartOS. Until then, do not rename a folder to a name made only of spaces. If a folder has already vanished this way, renaming it to a non-blank name restores it.

## Do not

- Do not treat the folder as deleted — its chats are not lost, the folder just has a blank name; renaming it to something visible brings it back.

## Notes

Folders already saved with a blank name are not repaired by the fix itself — they need to be renamed to a non-blank name to reappear normally in the sidebar.
