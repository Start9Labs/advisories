# Home Assistant: input_boolean/input_number/input_text helpers show "unavailable" after updating to 2026.9.1 or 2026.9.2

## Symptom

After updating Home Assistant Core to 2026.9.1 or 2026.9.2, helpers defined in YAML (`input_boolean`, `input_number`, `input_text`) — whether directly in `configuration.yaml`, in a package, or created through the GUI — show up in **Settings → Devices & services → Entities** but are marked "This entity is unavailable". They do not appear at all under **Developer Tools → States**. `ha core check` passes with no errors, and there is no error in the log naming the helper setup as the cause. Downgrading back to 2026.8.3 without changing any configuration makes the same helpers work again immediately. One user also reports the system becoming unresponsive when the helper count grows large (over ~150).

## Affects

Anyone running Home Assistant on 2026.9.1 or 2026.9.2 who defines `input_boolean`, `input_number` or `input_text` helpers, whether via YAML or the GUI. Not affected: users who stay on 2026.8.1 or earlier, or who don't use these helper types.

## Remedy

There is no fix yet. Customers hit by this should stay on or roll back to Home Assistant Core 2026.8.1, where these helpers work normally. Support should watch for a fixed release to be named upstream before advising an update past 2026.9.1.

## Do not

- Don't suggest editing or re-adding the helper YAML — the config is confirmed valid by `ha core check` and re-adding does not help.
- Don't treat this as a packages-only issue — it reproduces with a single helper directly in `configuration.yaml`.

## Notes

Unconfirmed: one reporter's note about the system becoming unresponsive above ~150 helpers may be a separate/related issue, not confirmed as the same root cause.
