# Jellyfin 12.0 upgrade fails to start with "SQLite Error 19: 'FOREIGN KEY constraint failed'" during ConsolidateLocalizedUserViews migration

## Symptom

After upgrading to Jellyfin 12.0, the server fails to start. The log shows the migration `20260825200000_ConsolidateLocalizedUserViews` failing with:

```
[ERR] Migration "20260825200000_ConsolidateLocalizedUserViews" failed
Microsoft.Data.Sqlite.SqliteException (0x80004005): SQLite Error 19: 'FOREIGN KEY constraint failed'.
```

The migration is then rolled back and Jellyfin does not complete startup.

## Affects

Jellyfin 12.0 installations upgrading from an earlier version whose SQLite database contains orphaned rows in `AncestorIds` (rows referencing `BaseItems.Id` values that no longer exist). Jellyfin automatically creates a pre-migration backup at `data/SQLiteBackups/` before attempting the migration.

## Cause

The pre-existing database had orphaned ancestry rows in `AncestorIds` left over from prior data, which violate a foreign key constraint that the `ConsolidateLocalizedUserViews` migration enforces.

## Remedy

This is fixed in Jellyfin 12.1. Update to 12.1 or later, which resolves the migration for databases with this kind of orphaned data.

## Do not

- Do not delete or reset the whole media library database — the underlying data is intact aside from orphaned index rows.

## Notes

Jellyfin automatically backs up the database before running migrations, so a failed migration does not itself destroy data. A user comfortable with SQLite could clean the orphaned rows directly from the pre-migration backup before retrying, but that is not a documented Start9 procedure and should not be given as a step.
