# Open WebUI: automations lose tool bindings and default features on the first run after a restart

## Symptom

After the server restarts, or after saving connection settings, the first automation run (chat or channel) answers as if it has no tools — MCP servers and other tool bindings are missing, along with default features like web search, default filters, and terminal. The model responds saying it has no tools available. Running the automation again, or manually clicking Regenerate, works normally. Automations that use the base models cache are not affected.

## Affects

Anyone using automations (scheduled tasks, channel bots, etc.) with a model that has tool bindings, MCP servers, or default features/filters configured, on the first run after a restart or after saving connection settings.

## Cause

The automation reads the model from an internal cache before anything has populated it. That cache stays empty after a restart or a connection settings save until a browser loads the model list or a chat completion runs — but the automation builds its request before that happens.

## Remedy

This is fixed upstream but not yet released in a StartOS package. The fix will be available once a release containing it reaches StartOS. Until then, if an automation's first run after a restart answers without its usual tools or features, running it again or clicking Regenerate gets the correct result.

## Notes

The same cold-cache condition also causes channel automations to show the raw model ID instead of the model's name on the first run; that resolves the same way.
