# Server goes unreachable after a day or three with the lights on; a forced restart brings it back — disable NVMe power saving (APST)

## Symptom

After a day or three of normal running the server drops off the network all at once — no UI, no SSH, no services, no `ping` — with the power light on and the Ethernet light blinking. A forced restart brings it straight back. The previous boot's journal stops mid-stream with no error before the gap, `/sys/fs/pstore` is empty, and memory, CPU and SMART tests pass. A monitor plugged in during the failure shows `SQUASHFS error: Unable to read metadata cache entry` repeating, or nothing at all.

## Affects

DIY servers on StartOS 0.4.0.1 and earlier with an NVMe OS drive, above all mini PCs whose firmware defaults to aggressive power saving. Confirmed on a Lenovo ThinkCentre M90q Gen 6 (Core Ultra 7 265T) with a Samsung 990 Pro. Not StartOS 0.4.0.2 or later, which disables APST and restarts a hung server itself.

## Cause

The drive enters its deepest autonomous idle state (APST) and never wakes. The OS root, an image on that drive, becomes unreadable while the kernel and network keep running. BIOS ASPM and C-state changes stretch the interval; only disabling APST ends it.

## Remedy

1. In the BIOS, disable PCIe ASPM and any NVMe or storage power saving, and limit CPU C-states.
2. If it still happens, add the kernel parameter `nvme_core.default_ps_max_latency_us=0` and restart. A StartOS update drops it again: after updating, check `/proc/cmdline` and re-apply.
3. Update to 0.4.0.2 when it is released; nothing needs re-applying after that.

## Do not

- Do not send them for a new power supply first; a larger one changed nothing in the confirmed case.
- Do not call it a corrupt install. Reflashing does not help.

## Notes

Nothing on 0.4.0.1 documents adding a kernel parameter, and the root is a tmpfs overlay, so `/etc/default/grub` and `/etc/modprobe.d` edits are gone on reboot. What holds is `sudo update-grub` output on the boot partition, which sources `/etc/default/grub.d/*.cfg`:

```
sudo mkdir -p /etc/default/grub.d
echo 'GRUB_CMDLINE_LINUX="$GRUB_CMDLINE_LINUX nvme_core.default_ps_max_latency_us=0"' | sudo tee /etc/default/grub.d/zz-nvme.cfg
sudo update-grub
sudo reboot
```

The name must sort after `raspberrypi.cfg`, which replaces `GRUB_CMDLINE_LINUX` on the Pi. `sudo nvme get-feature /dev/nvme0 -f 0x0c -H | head -n 1` shows `Current value:0x00000000` once APST is off. `gather-debug-info` on 0.4.0.1 collects neither the kernel log nor the previous boot; ask for `sudo journalctl -b -1 -n 300` and `sudo dmesg -T | tail -n 300`.
