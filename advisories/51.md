# Home Assistant: MELCloud Home devices go unavailable after an energy telemetry error — update to 2026.8.2

## Symptom

All MELCloud Home devices and entities suddenly show unavailable at the same time, even though the units still work fine in the official MELCloud Home app. The log shows an error fetching data, for example:

```
Error fetching melcloud_home data: Error communicating with MELCloud Home API
aiohttp.client_exceptions.ClientResponseError: 500, message='Internal Server Error', url='https://mobile.bff.melcloudhome.com/telemetry/telemetry/energy/...'
aiomelcloudhome.exceptions.MelCloudHomeConnectionError: Connection error: 500, message='Internal Server Error'
homeassistant.helpers.update_coordinator.UpdateFailed: Error communicating with MELCloud Home API
```

Devices can flip between available and unavailable repeatedly, sometimes several times within 20 minutes.

## Affects

Home Assistant Core 2026.8.1 and earlier, users of the MELCloud Home integration. Occurs when the MELCloud energy telemetry endpoint intermittently returns an HTTP 500, which previously took down the whole coordinator update — and with it every MELCloud Home device, not just the energy sensor.

## Cause

A failure of the (optional) energy telemetry request caused the entire MELCloud Home coordinator update to fail, marking all devices and entities unavailable instead of only the energy data.

## Remedy

Update Home Assistant Core to 2026.8.2 or later, where a failing energy telemetry request no longer takes down the rest of the MELCloud Home integration.

## Notes

After updating, some users still see log entries like `Failed to fetch energy telemetry for <device-id>`. A maintainer confirmed these are now tolerated/suppressed and reflect a limitation on Mitsubishi's side that is out of Home Assistant's control — devices stay available despite these log lines.
