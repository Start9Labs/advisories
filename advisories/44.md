# Jellyfin: upgrade to 12.0 fails with "SQLite Error 19: 'FOREIGN KEY constraint failed'" during ConsolidateLocalizedUserViews migration

## Symptom

Upgrade to 12.0 fails during startup migration `ConsolidateLocalizedUserViews` with:

`Microsoft.Data.Sqlite.SqliteException (0x80004005): SQLite Error 19: 'FOREIGN KEY constraint failed'.`

The migration is rolled back, the log shows `Main: Error while starting server`, and the server never becomes available. If the service is configured to restart automatically, it retries the same failing migration indefinitely.

## Affects

Users upgrading to Jellyfin 12.0 whose database contains orphaned `AncestorIds` rows — rows whose `ItemId` does not correspond to any row in `BaseItems`. In the reported case these were all associated with the Live TV view.

## Cause

Pre-existing orphaned rows in the `AncestorIds` table fail the `FK_AncestorIds_BaseItems_ItemId` foreign key constraint when the `ConsolidateLocalizedUserViews` migration rewrites ancestry rows during the move to 12.0.

## Remedy

A maintainer has asked the reporter to retry on 12.1; update to 12.1 or later before upgrading past 10.11.x if you hit this error.

As a workaround confirmed by the reporter, deleting the orphaned rows before upgrading allows the migration to complete:

`DELETE FROM AncestorIds WHERE ItemId NOT IN (SELECT Id FROM BaseItems);`

The rollback itself is safe: the database file's modification time, size, and integrity check are unaffected by repeated failed attempts, so no data is lost while working out a fix.

## Notes

Applying the workaround requires direct SQL access to the Jellyfin SQLite database, which is not exposed through the StartOS UI.

This is a different migration and table than the FOREIGN KEY failure covered by advisory 30 (`ConsolidateLocalizedUserViews`/`AncestorIds` here, vs. a different migration there), and also distinct from the orphaned-row failure in `RemoveOrphanedUserPermissionsAndPreferences` referenced in the upstream issue as a similar but separate bug.
