# Open WebUI: Unarchive All loses chat tags, and Delete All Chats leaves orphaned tag suggestions

## Symptom

After archiving a chat that has a tag (e.g. `alpha`) and then using **Unarchive All**, the chat comes back with no tags — the tag doesn't show on the chat, isn't offered in the tag suggestions, and re-adding it does nothing.

Separately, after tagging a chat and then using **Delete All Chats**, the tag is still offered in the tag suggestions and in search, even though no chat uses it any more.

## Affects

Anyone using the bulk **Unarchive All** or **Delete All Chats** actions on chats that have tags. Archiving or deleting a *single* chat, and unarchiving a single chat, are not affected — those already clean up and restore tags correctly.

## Cause

Archiving or deleting a single chat runs tag cleanup, and unarchiving a single chat restores tags, but the bulk Unarchive All and Delete All Chats actions skipped that step.

## Remedy

This is fixed upstream, but the fix has not shipped in any Open WebUI version available on the Start9 Registry yet. There is no workaround: a tag lost via Unarchive All has to be added back manually to each affected chat; a tag left behind by Delete All Chats can be ignored (it does nothing once no chat uses it) until the fix arrives. The fix will be available once a release containing it reaches StartOS.

## Notes

A related case — Archive All (archiving every chat at once) leaving unused tags in the suggestions — is reported separately upstream (open-webui/open-webui#30454) and is not part of this fix.
