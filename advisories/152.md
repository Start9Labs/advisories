# Open WebUI: clicking "Send now" on a queued message sends every queued message and corrupts the chat

## Symptom

With more than one message queued while a reply is streaming, clicking `Send now` on one of the queued messages sends all of them — two replies stream at once instead of just the one clicked. The clicked message shows as `2/2` and the `<` arrow to reach the other sibling does nothing. The `Overview` tab is empty or only partly drawn, sometimes logging a Svelte `each_key_duplicate` error in the browser console. Text from the other queued message's reply appears inserted into, or in place of, the interrupted reply. Deleting the message that shows `2/2` and clicking Confirm can freeze the page. Reloading the page, or leaving the chat and reopening it, fixes the display — the chat is then a correct straight thread, since only the open page's view was wrong, not the saved chat.

## Affects

Anyone using the message queue (on by default) who clicks `Send now` on a queued message while more than one message is queued during a streaming reply. Not hit if messages are left to send normally when the current reply finishes, or if only one message is ever queued at a time.

## Cause

Two problems combine: `Send now` stops the current reply without flushing the rest of the queue first, so the queue's own cancel handling sends the other queued message while the stop request is still pending; and the stop handler then writes the interrupted reply back into history under whatever message has become current by then, corrupting the parent/child links between messages.

## Remedy

This is confirmed and a maintainer has stated it is fixed in `dev`, but no Open WebUI release containing the fix has been published yet — none is stated as available or next. Tell the customer: reload the page, or leave the chat and reopen it, to restore the chat to its correct saved state — the underlying data is not lost, only the open page's view. Until the fix reaches a release, avoid clicking `Send now` when more than one message is queued; let queued messages send normally once the current reply finishes.

## Do not

- Do not tell the customer to delete the affected message to fix the view — deleting the `2/2` message can freeze the page instead.
- Do not treat the corruption as permanent — a reload or reopening the chat repairs the displayed thread without data loss.

## Notes

Upstream traces this to a regression introduced by commit f7767d6 (2026-08-13). Fix confirmed by a maintainer ("fixed in dev") on 2026-09-24, but not yet tied to a merged pull request number or a release; update this advisory once a version is named.
