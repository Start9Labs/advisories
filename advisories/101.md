# Nextcloud stuck on major version 32 after an interrupted update — `Cannot update Nextcloud from major version 32 directly to 34`, then `cannot migrate from 34.0.4:0 to 33.0.8:3` — update to 34.0.4:1

## Symptom

A server that migrated from StartOS 0.3.5.1 with Nextcloud still on major version 32 (the 33.0.8 package's upgrade never completed) gets `Cannot update Nextcloud from major version 32 directly to 34` on every 34 release. Installing the 33 release the error points to instead fails with `cannot migrate from 34.0.4:0 to 33.0.8:3`.

## Affects

Servers on Nextcloud 32 that attempted an update to a 34 release and were refused, then tried the 33 release named in the error. Servers already updated normally through 33 are not affected.

## Cause

The one-major-at-a-time guard ran after the data version had already been advanced to the refused 34 release and the 0.3.5.x layout migration had run. Because a package migrated from 0.3.5.x has no volume snapshot until its next boot, the failed attempt was not rolled back, leaving the data version stuck on a 34 release that no 33 release accepts.

## Remedy

Update to Nextcloud 34.0.4:1. The guard now runs before the data version is advanced, so a fresh attempt is refused cleanly with the installed package untouched. For a server already stranded on the invalid `34.0.4:0` data version, installing 34.0.4:1 resets it to the newest 34-package-compatible floor (`32.0.11:0`), which the 33 release then accepts and migrates through normally — no manual repair needed.

## Notes

If the server has rebooted since the failed 34 attempt, StartOS's own snapshot rollback may have already restored the stranded value; this fix applies regardless, since it also prevents the bad state from being reached at all. A related StartOS-side issue about snapshotting 0.3.5.x-migrated packages before their second boot is tracked separately (Start9Labs/start-technologies#3989) and does not need to be mentioned to the customer.
