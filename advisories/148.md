# Open WebUI: pressing Enter on a highlighted chat in the search dialog (Ctrl+K) closes it instead of opening the chat

## Symptom

In the search dialog opened with Ctrl+K, pressing Enter while a chat result is highlighted closes the dialog without opening that chat — the page stays where it was and nothing is logged. Clicking the same chat with the mouse opens it normally. Enter still works normally on the action rows at the top of the dialog, such as starting a new conversation.

## Affects

Anyone using the Ctrl+K search dialog to find and open an existing chat by keyboard. Opening a chat by clicking it with the mouse is unaffected, as is using Enter on the dialog's top action rows (e.g. New Chat).

## Cause

A chat menu was added to search results, and each result's link now sits inside the row rather than at the row's top level. Enter triggers a click on the row itself, which no longer reaches the link, while the dialog still closes.

## Remedy

This is confirmed by a maintainer and a fix is in progress upstream (linked pull request #31004), but is not yet available in any released version. Until a release containing it reaches StartOS, tell the customer to click the desired chat with the mouse instead of pressing Enter to open it from the search dialog.

## Do not

- Do not suggest reinstalling or reconfiguring Open WebUI — this is a UI keyboard-handling bug, not a configuration issue.

## Notes

Reported against the `dev` branch; the fix's release version is not yet known. Update this advisory once a package version is published stating the fix is included.
