# Firefly III: CSV import duplicates the last row on re-import

## Symptom

Re-importing the same CSV file correctly skips duplicate transactions except for the very last row, which gets imported a second time as a new transaction. The debug log shows earlier rows submitted with `"batch_submission":true` while the final row is submitted with `"batch_submission":false`, and it bypasses the duplicate check that catches the other rows.

## Affects

Anyone using the CSV importer with duplicate detection (`duplicate_detection_method: classic`, `ignore_duplicate_transactions: true`) to re-import a file that has already been imported, or that overlaps with a previous import. The last row of the file is the only one affected.

## Cause

The importer submits all rows but the last one as part of a batch; the final row is submitted individually with `batch_submission` set to false, which skips the duplicate check applied to the rest.

## Remedy

This is fixed for the next Firefly III release, targeted for v6.7.0. Until then, after a re-import check the last transaction created and delete it manually if it is a duplicate.

## Notes

Reported against v6.6.6; a maintainer confirmed it as a bug and fixed it for the upcoming release. No fixed version has shipped yet.
