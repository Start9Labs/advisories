# Open WebUI: response view stops auto-scrolling partway through a streamed answer from reasoning models

## Symptom

With **Response Auto-Scroll** turned on, the chat view follows a streaming response during the model's "thinking"/reasoning phase, then stops following right as the reasoning block collapses and the answer begins. The answer keeps growing without the view scrolling to it, and the view only jumps to the bottom once generation finishes. No error appears in the browser console. It reproduces reliably with any model that streams reasoning separately (e.g. via a reasoning parser or hybrid-thinking mode) and a moderately long answer; it does not reproduce with short answers or with models that stream plain content only.

## Affects

Open WebUI 0.11.0, 0.11.1 and 0.11.3 as shipped by StartOS, when using a model/connection that streams a separate reasoning phase before the answer and Response Auto-Scroll is enabled. Not seen with non-reasoning models.

## Cause

The per-update auto-scroll check in the chat view re-derives whether to keep following purely from a ~50px distance-from-bottom test. The reasoning block's collapse/reflow at the thinking→answer handoff can transiently push the view more than 50px from the bottom, which the code reads as the user having scrolled up, disabling auto-follow for the rest of the stream.

## Remedy

Fixed on the upstream `dev` branch (commit `dfde08aa7391d924359b27f5768411d7a533a6ec`), which restores scrolling to the bottom on every streamed delta rather than only at the end. The fix has not yet shipped in a release; none of the versions StartOS currently ships (0.11.4:0, 0.11.3:1, 0.11.1:0, 0.11.0:3, 0.10.2:5, 0.9.6:2, 0.9.5:1, 0.9.2:1, 0.8.12:2) include it. Until it does, scroll down manually to follow the answer after the reasoning block closes.

## Notes

Reported independently against 0.11.3 by more than one user, including with models that emit no reasoning at all — that may be a related but separate cause and is not confirmed fixed by the same commit.
