# Transfer flow leaves the server at "start9.local" with a certificate for the old hostname — fix ships in 0.4.0.2

## Symptom

After transferring data from one disk to another (via the pre-setup Transfer flow), the new server is reachable only at `http://start9.local` instead of its original hostname. The certificate it presents (`start9.crt`) is still signed for the original server's hostname — for example a CN of `smoke-too-much Local Root CA` — so the address you land on and the certificate you're asked to trust don't match.

## Affects

Anyone who uses the Transfer flow to move a StartOS installation from one disk to another. Not related to a normal OS update or backup restore.

## Cause

The transfer did not carry over the original server's hostname, so the transferred-to server falls back to the default `start9.local` name while still handing out the original server's certificate.

## Remedy

Update to 0.4.0.2, which is next: a transfer now keeps the existing server name (or repairs it automatically if it is over the length limit), so the hostname and certificate match again.
