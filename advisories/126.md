# Ride The Lightning login fails first attempt with "Invalid Csrf Token, Form Tempered"

## Symptom

Logging into RTL fails on the first attempt with `Invalid Csrf Token, Form Tempered`. Typing the same password again immediately succeeds. This happens again every time the RTL container restarts.

## Affects

Anyone opening RTL at its root address (`/rtl/` or `/rtl`) after a fresh container start, including after any RTL restart or update. Landing on `/rtl/login` directly (e.g. via a refresh, bookmark, or a logout redirect) is not affected — the token is minted correctly there.

## Cause

The CSRF token cookie is only set by the handler that serves deep links (`/rtl/login`, `/rtl/home`, …). The root address is served by a static-file handler that sits above that logic and never sets the cookie, so the page loads with no valid token and the first login POST is rejected with HTTP 403. The server mints a token on that failed response, so the second attempt works. Since 0.15.10, tokens are also signed with a secret generated at startup, so any token from before a restart is invalid too — making this show up every time the container restarts.

## Remedy

No update is available yet: this affects the current release 0.15.12:0 and is fixed only in RTL v0.15.13, not yet published on the Start9 Registry. Until it is, retype the password and log in a second time — it succeeds — or navigate to `/rtl/login` instead of the root address, which mints the token correctly the first time.

## Notes

A browser tab left open across an RTL restart will still fail its first login once after the restart, since its token becomes void; retrying works the same way.
