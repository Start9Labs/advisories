# Jellyfin: upgrade to 12.0 fails with "Error loading configuration file: /config/encoding.xml" and resets transcoding settings

## Symptom

After updating to Jellyfin 12.0, the log shows:

```
[ERR] Error loading configuration file: "/config/encoding.xml"
System.InvalidOperationException: There is an error in XML document (30, 35).
 ---> System.InvalidOperationException: Instance validation error: '' is not a valid value for EncoderPreset.
```

Transcoding and hardware acceleration settings (e.g. QSV, NVENC) are reset to default after the update.

## Affects

Anyone updating from 10.11.11 (or earlier) to 12.0 whose `encoding.xml` has no encoder preset selected, which serializes as `<EncoderPreset xsi:nil="true" />`. Jellyfin 12.0 made `EncoderPreset` non-nullable, so this old value fails to load and the whole file falls back to defaults, including hardware acceleration.

## Cause

In older versions `EncoderPreset` was nullable and an unset preset was stored as `<EncoderPreset xsi:nil="true" />`. Jellyfin 12.0 changed the field to non-nullable, and there is no migration for existing config files, so this value fails XML deserialization.

## Remedy

Re-select the transcoding and hardware acceleration settings in the Playback settings and restart Jellyfin; this rewrites `encoding.xml` with a valid `EncoderPreset` value and the error clears.

## Notes

The `encoding.xml` file itself can also be repaired directly by replacing `<EncoderPreset xsi:nil="true" />` with `<EncoderPreset>auto</EncoderPreset>`, but doing so requires editing the file inside the service's data directory, which is outside the StartOS UI.
