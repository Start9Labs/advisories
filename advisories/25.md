# Miele integration fails with "Oops... an error occurred" when adding it

## Symptom

Adding the Miele integration fails during the OAuth sign-in step. The browser shows an "Oops... an error occurred" page from Nabu Casa (sometimes preceded by an HTTP 500 error), and the setup does not complete. Removing and re-adding Miele credentials, clearing browser cache, or trying different browsers does not help.

## Affects

Home Assistant users adding the Miele integration without first configuring their own application credentials. The integration silently defaults to using Nabu Casa's cloud account-linking service for OAuth, which has been failing on the callback step. Users who already have application credentials configured for Miele are not affected.

## Cause

When no application credentials are configured for Miele, the integration falls back to `CloudOAuth2Implementation`, which routes the OAuth callback through `account-link.nabucasa.com`. That Nabu Casa endpoint has been intermittently returning errors on the callback, causing the config flow to fail.

## Remedy

Tell the customer to bypass the broken Nabu Casa cloud link by configuring their own Miele application credentials:

1. Register a developer account at the Miele Developer Portal (developer.miele.com) — use the same email address as the Miele app account.
2. Once approved, get the client ID and secret from the developer portal.
3. In Home Assistant, go to Settings → Devices & Services → Application Credentials, and add a new credential of type "Miele" using that client ID and secret.
4. Add the Miele integration again; on the first screen, select the application credential just created, then complete the OAuth sign-in.

This uses the local OAuth implementation instead of the Nabu Casa cloud link and avoids the broken endpoint.

## Do not

- Don't tell the customer to just clear cache, try another browser, or remove/re-add Miele credentials in the Miele app — several users tried this without success; the fix is bypassing the Nabu Casa cloud link entirely.

## Notes

The upstream issue was closed as stale/not planned without a code fix; the application-credentials workaround is the only confirmed remedy at this time.
