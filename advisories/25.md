# Zones with duplicate names both show "occupied" when only one is entered

## Symptom

A person/device is physically in only one zone, but every zone that shares the same name changes state to occupied (count goes to 1, `persons` attribute populated) simultaneously. Reported on core-2026.3.4.

## Affects

Home Assistant (packaged as home-assistant) installations with two or more Zone entities that have the same friendly name. Zones with distinct names are not affected.

## Cause

The zone integration compared a tracked entity's state string against the zone's name rather than checking its actual coordinates against the zone's geofence, so any zone sharing that name matched.

## Remedy

Update to Home Assistant Core 2026.7.0 or newer, which contains the fix (home-assistant/core#173074). Until then, give each zone a unique name to avoid the false positives.

## Do not

- Don't rename a zone via the entity settings (more-info → cog) dialog as a workaround — a separate, unresolved issue causes the zone to stop updating state entirely afterward.

## Notes

The reporter also described a second, distinct problem: renaming a zone through the UI entity settings dialog can make it stop changing state at all. That issue was still unconfirmed/uninvestigated by maintainers as of the last update — treat as a separate unresolved report, not covered by this fix.
