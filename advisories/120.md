# Open WebUI: collapsing the task list above the message box sends the message you were typing

## Symptom

While a tool-calling response is streaming and the task list panel appears above the message input, clicking the chevron to collapse that panel instead submits whatever message is currently typed in the input box — the panel collapses and the in-progress draft is sent as a chat message.

## Affects

Anyone using a tool-calling model (e.g. the built-in Tasks tool) with a multi-step response, who types a next message while the task panel is still shown above the composer and clicks to collapse it on Open WebUI versions before 0.11.4:0. Does not affect the same panel when it appears inside a completed response message (not in the input form), and does not affect sending via Enter or the send button.

## Cause

The task list panel's collapse button has no `type` attribute, so browsers treat it as a form submit button. The panel is reused inside the message composer's form, whose submit handler sends the typed message; the fix adds `type="button"` to the collapse control.

## Remedy

Update to Open WebUI 0.11.4:0 or later.

## Do not

- Don't treat this as a UI freeze or bug in the tool call itself — the response continues normally; only the typed draft is unexpectedly sent.
