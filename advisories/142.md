# Open WebUI: pressing M to mute during a voice call types "m" into the chat box instead

## Symptom

During a voice call, pressing **M** after a turn does not mute — instead an "m" is typed into the chat input box. This happens because after each voice message the chat input pulls keyboard focus back to itself, and the call overlay ignores the M shortcut while focus is in a text field.

## Affects

Anyone using Voice Mode for more than a single turn, in both new and existing chats. Clicking into the input and typing during a call is unaffected — that always worked.

## Cause

The chat input regained keyboard focus after each voice message was sent, on the remount for a new chat's first message, and via the editor's autofocus — all while a call was open, stealing focus away from the call overlay that listens for M.

## Remedy

This is fixed upstream (merged as of 2026-09-24) but not yet in a released version. Once a package version containing the fix is available, updating resolves it — the chat input stops re-focusing itself during a call so M reaches the call overlay as a mute toggle. Until then, mute by clicking the mute control in the call overlay instead of pressing M.

## Notes

Fix merged upstream in open-webui/open-webui#30421; no Open WebUI release has been recorded as containing it yet.
