# Open WebUI: closing the admin Edit User dialog without saving still applies the change on the next save

## Symptom

In Admin Panel → Users, editing a user (for example changing Role from User to Admin) and then closing the dialog with the X instead of clicking Save appears to discard the change. But reopening that same user's dialog still shows the abandoned value in place, and saving any other field (e.g. just the Name) writes the abandoned change to the account as well — including a Role change, which can promote or demote the account. Nothing is logged to the server or browser console.

## Affects

Anyone using the admin Edit User dialog (Admin Panel → Users → edit) prior to the fix. Not limited to Role — any field left changed and then closed without saving could be committed on the next save of that user.

## Cause

The dialog filled its form from the same object reference used by the user list row instead of a copy, so any edit mutated the list's row directly. Closing the dialog did not reload the list, so reopening it showed the mutated row, and the next save sent the whole (now-mutated) object. The same defect was previously fixed for the Edit User Group dialog.

## Remedy

Fixed: the Edit User dialog now copies the row into its own form model instead of sharing the list's object, so closing without saving discards the edit. Update to a version including this fix.

## Notes

Merged fix (PR #30193) also confirmed the blank password field is no longer written back onto the list row as a side effect of the same copy.
