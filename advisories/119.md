# Open WebUI: closing the admin Edit User dialog without saving still applies the change on the next save

## Symptom

In Admin Panel → Users, editing a user (for example changing Role from User to Admin) and then closing the dialog with the X instead of clicking Save appears to discard the change. But reopening that same user's dialog still shows the abandoned value in place, and saving any other field (e.g. just the Name) writes the abandoned change to the account as well — including a Role change, which can promote or demote the account. Nothing is logged to the server or browser console.

## Affects

Anyone using the admin Edit User dialog (Admin Panel → Users → edit) on the default configuration. Not limited to Role — any field left changed and then closed without saving can be committed on the next save of that user.

## Cause

The dialog fills its form from the same object reference used by the user list row instead of a copy, so any edit mutates the list's row directly. Closing the dialog does not reload the list, so reopening it shows the mutated row, and the next save sends the whole (now-mutated) object. The same defect was previously fixed for the Edit User Group dialog.

## Remedy

No fix has shipped yet. Until one does, treat any edit made in the Edit User dialog as retained even after closing without saving: after closing that dialog without saving, reopen the same user and check every field before saving anything else for that account, and correct or reset any field that still shows the abandoned change before saving.

## Do not

- Assume closing the dialog with the X discarded the edit — it did not; the field is silently retained and will be saved the next time that user's dialog is saved.

## Notes

No fix version has shipped yet. Until it does, treat the Edit User dialog as "unsaved changes persist" and verify a user's Role/fields after any edit session on that account, even one closed without saving.
