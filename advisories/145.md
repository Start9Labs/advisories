# Open WebUI: Code Interpreter fails with `ModuleNotFoundError` on code that only mentions matplotlib

## Symptom

Running Python code in the Code Interpreter fails with `ModuleNotFoundError`, even though the code never imports or uses matplotlib — it only mentions the word "matplotlib" in a comment, a string, or a check like `importlib.util.find_spec("matplotlib")`. The error happens before any of the user's code runs, so a `try`/`except` around it does not help. The built-in Python code formatter can fail the same way on any code that imports matplotlib, since formatting only installs `black`.

## Affects

Anyone using Open WebUI's Code Interpreter (or the code editor's Python formatter) with code that references "matplotlib" in a comment, string, or capability check without actually importing and using it. Code that genuinely imports and uses matplotlib to plot is unaffected and continues to render inline PNG output from `plt.show()`.

## Cause

A patch that intercepts `plt.show()` to capture plots as inline images was applied whenever the code contained the substring "matplotlib," regardless of whether matplotlib was actually imported. Since matplotlib is only installed in the runtime when actually imported, the patch's own attempt to use it crashed the run before the user's code executed.

## Remedy

This is fixed upstream: the patch now also checks that matplotlib is actually present in the runtime's loaded packages before applying, in both the worker and the sandboxed iframe host. The fix has not yet reached a released version of the Open WebUI package — no release since the merge contains it. Once a release containing the fix reaches StartOS, updating to it resolves this.

## Notes

Gating on a regex match of the caller's own import statement was tried and rejected, because the formatter's failure case has the import sitting inside a string while only `black` is installed — that fix would not have caught it.
