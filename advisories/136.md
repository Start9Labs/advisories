# Open WebUI: admin panel's list of a user's chats goes empty after deleting one of them — reopen it to see the rest

## Symptom

In the admin panel, viewing a user's list of chats and deleting one of them causes the list to go empty, even though the user still has other chats. Closing and reopening the list shows the remaining chats normally.

## Affects

Admins deleting a chat from a user's chats list in the Admin Panel, particularly when the list is short enough that the deletion has already caused it to page ahead internally. Not the user-facing chat list or the archived chats list.

## Cause

After a delete, the list reloaded whatever page of results it had last loaded rather than starting over. With a short list, loading more results had already advanced it past the first page, so reloading that later (empty) page replaced the whole list with nothing.

## Remedy

This is fixed upstream, merged into Open WebUI's `dev` branch. It has not shipped in a release yet — there is no version to update to at this time. Once a released version of Open WebUI contains this fix, the admin chats list will keep showing the remaining chats after a delete, starting again from the first page as intended. Until then, if the list goes empty after deleting a chat, closing and reopening it shows the remaining chats.

## Notes

Unreleased as of this writing: no Open WebUI version available on the Start9 Registry contains this fix yet.
