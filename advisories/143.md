# Open WebUI: Read Aloud auto-playback is silent on iOS/iPadOS and the speaker button gets stuck on "speaking"

## Symptom

On iPhone or iPad, a finished reply's auto-playback is never heard, and the Read Aloud speaker button stays stuck showing "speaking" — the first tap only stops a playback that never actually started. Call Mode on the same devices is silent too.

## Affects

Users on iOS or iPadOS (Safari/WebKit-based browsers, including WebKit-based browsers on those platforms). Not seen on desktop browsers.

## Cause

WebKit rejects a `play()` call started from a network event (rather than a direct user gesture), and Open WebUI's audio queue did not handle that rejection, leaving the button stuck and later chunks dropped. Call Mode additionally hit a WebKit restriction that pauses an unmuted element played outside a user gesture.

## Remedy

This is fixed upstream but not yet released. Once released, a rejected playback resets the queue and returns the button to idle with a toast shown, and the first tap or keypress after loading unlocks audio playback for the rest of the session; Call Mode plays unmuted correctly. The fix will be available once a release containing it reaches StartOS.

## Notes

Unconfirmed: no user reports yet beyond the reporter's own iOS 27 / iPadOS 26.6.2 testing; filed here because it is a maintainer-authored fix for a symptom on a screen (Read Aloud / Call Mode) many mobile users would hit.
