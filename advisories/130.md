# Open WebUI: system prompt is dropped from later requests after a tool call (e.g. Knowledge search)

## Symptom

A system prompt is set (for example, instructions to always tool-call and to format the final answer a certain way), and the first request sent to the model includes it correctly. But once a tool call happens (such as a Knowledge base search), the system prompt is missing from the follow-up request that includes the tool's result — the model then answers generically, ignoring the system prompt's instructions, as if it had never been given them.

## Affects

Chats where a tool is invoked (e.g. Knowledge search / `query_knowledge_files`) mid-conversation, especially with Native function calling. Reproduced with Ollama; not confirmed to be Ollama-specific. Chats that never trigger a tool call are unaffected.

## Cause

The system prompt is not being re-included when the conversation is re-sent to the model after a tool call's result is added.

## Remedy

A maintainer has linked a fix (open-webui/open-webui#30375). No release has shipped it yet — support cannot point to a version, so track this in the tracker until it ships and check back for an updated advisory.

## Notes

Reported against Open WebUI v0.11.3. If a system prompt appears to "stop working" only in chats that use tools, this is likely the cause; check whether the chat's own per-chat System Prompt box was touched (see advisory 128) as a look-alike before assuming this one.
