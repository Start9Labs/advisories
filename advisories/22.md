# Photos with named face tags never get thumbnails; metadata job fails silently

## Symptom

After enabling **Import faces from metadata**, assets whose XMP (embedded or sidecar) contains a named face region for a person not yet known to Immich never get a thumbnail, and never run smart search, face detection, or OCR. Tags and EXIF from the same file do appear. The server log shows:

```
PostgresError: column "clusterGroupId" of relation "person" does not exist
sql: insert into "person" ("personGroupId", "ownerId", "clusterGroupId", "name") values ($1, $2, $3, $4) returning *
```

followed by:

```
Unable to run job handler (AssetExtractMetadata): PostgresError: column "clusterGroupId" of relation "person" does not exist
```

The job fails entirely and there is no visible error in the UI — the asset just sits without a preview until someone runs *Regenerate thumbnail* on it manually.

## Affects

Immich v3.2.0, with **Import faces from metadata** enabled, when a photo's XMP names a person who does not already exist in that user's Immich. Named regions for people who already exist as persons are unaffected. Fixed in v3.2.1.

## Cause

A code path added for cluster groups included `clusterGroupId` in the row object used to insert new `person` records, but the `person` table has no such column (only `person_group` does). The insert fails, aborting the whole metadata-extraction job for that asset.

## Remedy

Update the Immich service to v3.2.1 or later, which contains the fix. If already on v3.2.1+, this should not occur. For anyone still on v3.2.0: turn off **Import faces from metadata** (Administration → Settings → Metadata) until updating — metadata extraction, thumbnails, and search then work normally, and named face regions are picked up once the fix is in place and *Refresh metadata* is run.

## Notes

- Assets already affected (missing thumbnail, no faces) on v3.2.0 need a manual *Regenerate thumbnail*, or a metadata refresh after updating to v3.2.1, to pick up the tagged faces.
- Only triggers when a region names a person not yet in that user's person list, which is why it can go unnoticed on instances where most named people already exist.
