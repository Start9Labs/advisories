# Open WebUI: clearing a chat's own System Prompt box stops your personal system prompt from applying to that chat

## Symptom

A personal system prompt is set in Settings → General, and normally every chat uses it. But if a chat's own System Prompt box (in that chat's Controls panel) is typed into and then emptied out, the personal system prompt stops applying to that chat — even though the box looks empty and untouched. The chat keeps ignoring the personal prompt after reloading the page and for every later message sent in it. New chats are unaffected.

## Affects

Anyone who sets a personal system prompt in Settings → General and, in some chat, opens that chat's own System Prompt box and clears it back to empty (rather than never touching it). Chats that never had their own System Prompt box touched are not affected.

## Cause

Emptying the chat's own System Prompt box is supposed to make the chat fall back to the personal system prompt. Instead, the chat kept sending an empty system prompt in place of the personal one, and because chat controls are saved, the chat stayed that way through reloads and future messages.

## Remedy

Fixed upstream (open-webui/open-webui#30333, merged 2026-09-22). No Open WebUI release on the Start9 Registry yet includes it; the latest available is 0.11.3:1. There is no in-app setting to work around it: recreate the chat, or start a new one, to restore the personal system prompt until an update carrying this fix is published.

## Notes

The fix does not repair chats that already carry the stuck empty prompt on their own — a chat in that state is fixed the next time it is used after updating, per the upstream verification notes.
