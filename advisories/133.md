# Cannot log in via an IPv6-literal address — "invalid request signature"

## Symptom

Signing in to the StartOS UI from an IPv6-literal URL (for example `https://[2001::abcd]/`, or through a tunnel like `http://[::abcd]:<port>/`) fails with an error like:

```
RPC ERROR: Unauthorized. Invalid request signature: not valid for any identity this server recognizes (hostname, domain, or IP address); the request was likely signed for a different server identity or by an incompatible client.
```

The same failure happens with `start-cli` pointed at an IPv6 host.

## Affects

Anyone reaching the StartOS UI or using `start-cli` via an IPv6-literal address (bracketed, as browsers and start-cli both render it). IPv4 addresses and named hosts (`.local`, `.onion`, domains) are not affected.

## Cause

Browsers and start-cli sign the request against the bracketed form of the host (`[::abcd]`), but StartOS stored and offered IPv6 hostnames unbracketed (`::abcd`) when checking the signature, so the two never matched.

## Remedy

This is fixed and will be available once a release containing it reaches StartOS.

## Notes

The fix is merged but not yet released; StartOS 0.4.0.2 is next.
