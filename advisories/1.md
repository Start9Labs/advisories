# Bitcoin Knots installed from a third-party registry follows a different blockchain — StartOS dependents accept it as Bitcoin, and there is no migration back to Core

## Symptom

A user has installed, or is asking about, a service called **Bitcoin Knots** obtained from a registry that is not the Start9 Registry or the Community Registry. StartOS raised no objection when they installed services against it, but its block height does not match Bitcoin's, expected transactions never appear, and no option is offered to switch it to Bitcoin Core. Those dependent services may separately show Bitcoin as an unsatisfied dependency, which is confusing on top of everything else. Just as often they simply ask whether it is safe to install.

## Affects

Anyone who installed Bitcoin Knots from a registry other than the Start9 Registry or the Community Registry, and every service on that server that depends on Bitcoin.

## Cause

That package uses the `bitcoind` package ID and the `knots` flavor, and declares that it satisfies Bitcoin Core revisions `28.4:23` and `29.4:10`. Its own version satisfies no ordinary Bitcoin version range — those two declarations are the entire reason anything accepts it. The Marketplace honours them, so it offers the install and warns nobody, while a service's own dependency check does not read them and can report Bitcoin as unsatisfied once installed. The two layers disagree, which is why the situation looks inconsistent rather than simply broken. It is not Bitcoin: it follows the chain that split from Bitcoin at BIP-110 (RDTS) and then hard-forked to a different proof-of-work algorithm.

## Remedy

- **Not yet installed** — do not install it unless they specifically intend to run that chain and understand that nothing else on their server should be pointed at it.
- **Already installed** — StartOS will not migrate it back. Bitcoin Core and Bitcoin Knots (pre-RDTS) both refuse a migration from it, so no flavor switch is offered and none can be made to appear. Returning to Bitcoin means uninstalling it and installing Bitcoin Core fresh, and that is a full re-sync — the data directory holds the other chain's blocks and cannot be reused.
- **A Lightning node or wallet has been running against it** — escalate to a human. Its channel and wallet state was built against a different chain, and what can be recovered is not a question to answer from this entry.

## Do not

- **Do not describe that chain as broken, stalled, or failing to produce blocks.** It produces blocks normally. It is a different network, not a malfunctioning one — saying otherwise is wrong and the user can immediately see that it is wrong.
- **Do not suggest switching flavors as the fix.** StartOS offers no such switch here. Telling someone to look for one wastes their time and costs you the rest of the answer.
- **Do not confuse it with Start9's Bitcoin Knots.** Start9 publishes **Bitcoin Knots (pre-RDTS)** on the Community Registry; that one follows the same chain as Bitcoin Core, and switching between it and Core is supported and safe. Establish which registry a user's Knots came from before saying anything else about it.
- **Do not present it as vetted or supported.** Start9 does not vet, endorse, or support services from registries other than the two that ship with StartOS.

## Notes

- Services that accept it as Bitcoin include LND, Core Lightning, BTCPay Server, Fulcrum, electrs, Mempool, Specter, Bisq, Jam, Bitcoin Explorer, Fedimint, Public Pool, UTXOracle and Wasabi — the great majority of anything that depends on Bitcoin. Dojo, Eclair and Stratum V2 happen to require Bitcoin Core 31.x and therefore reject it.
- Both Electrum servers accept it, which matters because that is the path most wallets use to reach a node.
- The user did nothing wrong and nothing about their server is misconfigured. This is a package from elsewhere presenting itself as a flavor of Bitcoin, and StartOS taking that declaration at face value.
- Start9 is in contact with the registry's operator about changing the package ID so that it presents as a separate stack rather than a flavor of Bitcoin. Until that happens, this remains live.

Known since 2026-09-03.
