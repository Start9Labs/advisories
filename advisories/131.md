# Datum Gateway stratum port unreachable from a separate VLAN or routed subnet on the LAN interface

## Symptom

A device on a different subnet than the StartOS host's own LAN (for example a separate VLAN routed to the host, with routing and ACLs confirmed to allow the traffic — `ping` succeeds) cannot reach Datum Gateway's stratum port. `nc -zv <host-ip> 23334` fails, and Datum Gateway logs nothing at all about the attempt.

## Affects

Anyone exposing Datum Gateway's stratum port as a `Local` interface and connecting from a subnet other than the StartOS host's own on-link LAN subnet — e.g. a routed VLAN. Devices on the same subnet as the StartOS host are not affected. The StartOS admin UI and other web UIs are not affected — they accept any private-range source; this is specific to raw non-SSL ports like stratum.

## Cause

A `Local` exposure is source-filtered by StartOS's generated nftables rules to only the subnets it already knows about (the host's on-link LAN subnet, the internal bridge, loopback, and the WireGuard/overlay subnet). There is no UI or config option to add another client subnet, so a connection from a separate routed subnet is dropped before it reaches Datum Gateway. Confirmed as StartOS behavior, not a Datum Gateway bug, and tracked upstream at Start9Labs/start-technologies#3912.

## Remedy

There is no fix yet. As a stopgap, a matching `nft add rule` entry for the new subnet (mirroring the existing per-subnet DNAT+masquerade pattern) restores connectivity, but it does not persist — it is lost on reboot or on any config change that regenerates the service's networking, and has to be re-added each time.

## Do not

- Do not treat this as a Datum Gateway misconfiguration or routing problem — routing, ACLs and masquerade all work; only the source-subnet filter on the `Local` exposure blocks it.
- Do not expect the manual `nft` rule to survive a reboot or a service config change.

## Notes

StartOS maintainers are still deciding, as of this writing, whether `Local` should uniformly accept any private-range source (matching web UI behavior) or remain restricted to the on-link subnet for raw ports before shipping a fix — see Start9Labs/start-technologies#3912.
