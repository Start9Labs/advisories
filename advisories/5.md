# The StartOS UI's http:// .onion address times out on 0.4.0 and 0.4.0.1 — use the https:// one

## Symptom

On StartOS 0.4.0 or 0.4.0.1, the `http://` `.onion` address for the **StartOS web interface itself** never loads — it hangs until the browser gives up, with no error naming a cause. The `https://` `.onion` for the same interface works normally, and `.onion` addresses for installed *services* work normally. Affected servers often have several `http://` addresses listed for the interface and all of them fail.

## Affects

StartOS 0.4.0 and 0.4.0.1, and only the StartOS interface's own http:// .onion address. Its https:// address and every service's .onion are unaffected, as are fresh 0.4.0.2 installs and servers updated to it.

## Cause

The StartOS interface's unencrypted port was assigned a high, arbitrary number on these versions, and the server's own firewall rule for that port sends it somewhere that discards it. The address is published correctly and Tor forwards to it correctly; nothing answers at the other end. The hang rather than a refusal is the signature — the packet is dropped, not rejected.

## Remedy

Use the **`https://`** `.onion` address for the StartOS interface. It is on the same Interfaces page and serves normally. That is the whole answer today.

**What happens on the fix.** StartOS 0.4.0.2 corrects it in two ways at once: the interface's unencrypted port returns to its normal number, and the firewall rule that discarded it is no longer created. Tor then re-points the user's existing `.onion` addresses by itself the next time it starts. **Every address they already have comes back — nothing to re-add, and no address is lost.** Tell them to wait for 0.4.0.2 rather than change anything.

## Do not

- **Do not suggest creating a new `.onion` address.** A newly generated one fails in exactly the same way; this has been tested. It is not a per-address problem.
- **Do not suggest deleting an address.** Removing the last port on a `.onion` deletes its key material and the address is gone permanently.
- **Do not suggest updating, reinstalling, or resetting the Tor service.** Tor is behaving correctly; it cannot see that the address the OS gave it does not answer.

## Notes

- Affects StartOS 0.4.0 and 0.4.0.1. Fresh 0.4.0.2 installs and servers updated to it are unaffected.
- Only the StartOS interface is affected. A service whose own `http://` `.onion` fails is a different problem — diagnose it normally.
- If their `https://` `.onion` also fails, this is not this issue.

Known since 2026-08-25.
