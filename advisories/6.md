# Electrs: wallets stop connecting after upgrading from 0.3.5.1 — the port that was plain TCP is now SSL

## Symptom

After a server is upgraded from StartOS 0.3.5.1 to 0.4.x, wallets that were already connected to Electrs stop connecting. Sparrow reports "Retries exhausted"; Electrum, Trezor Suite, BlueWallet and others fail with an equally generic timeout. Nothing in the error mentions TLS or certificates. Electrs itself is healthy and fully synced and reports "Electrum Server is ready and accepting connections", which is why this reads as a network or sync problem and is not one.

## Affects

Servers upgraded from StartOS 0.3.5.1 with Electrs installed. Fresh 0.4 installs are unaffected.

## Cause

On 0.3.5.1 the Electrum interface was plain TCP on port 50001. On 0.4 it is served over TLS, and on upgraded servers TLS ended up on the number 50001 — so the port the user already has saved is now the SSL port, and their wallet is still speaking plaintext to it. A plaintext port still exists but moved to a high-numbered one that is reachable only on the server itself, never from another machine.

## Remedy

**Remedy — LAN / `.local` / domain address. This is the whole fix for most people.**

1. Electrs → **Interfaces** → **Electrum (SSL)**. Copy the address shown there. **Do not assume port 50002** — on upgraded servers it is usually 50001, and whatever is shown is correct and permanent for that server.
2. Turn the wallet's SSL option **on**, keeping that same port:
   - **Sparrow**: Preferences → Server → Private Electrum → **Use SSL** on
   - **Electrum desktop**: server entry with the `s` suffix, e.g. `host:50001:s`
   - **Trezor Suite**: custom Electrum server as `host:50001:s` (`:s` = SSL, `:t` = plain TCP)
3. Accept or trust the certificate when prompted. It is issued by the user's own StartOS root CA — Electrum pins it on first use, Sparrow shows a one-time trust prompt.

**Remedy — Tor (`.onion`), only if the `.onion` specifically also stopped working.** Not every upgraded server is affected here, so confirm the `.onion` itself is failing before touching it.

1. Electrs → **Interfaces** → **Electrum (SSL)** → the **Tor** section → the **Add Onion Service** button.
2. Under *Address*, choose the **existing `.onion`** from the list — not "Create new address" — and turn **SSL** on.
3. The Tor section now shows a second row for the same `.onion` on a different port. Point the wallet at that row, with SSL on.

## Do not

**Never tell a user to delete their only Tor address for Electrs.** Removing the last port on a `.onion` deletes its key material and the address is gone permanently. Add the SSL row first. The old row can be deleted afterwards if they want it tidy, and is harmless left alone.

## Notes

- Affects servers upgraded from 0.3.5.1 with Electrs installed. Fresh 0.4 installs are not affected — they serve TLS on 50002 as documented.
- A StartOS fix is on the way. There is nothing the user needs to wait for and nothing they did wrong; the steps above are the answer today and will keep working.
- **Fulcrum**: the wallet-side advice is the same (SSL must be on, take the port from the Interfaces page) but for an ordinary reason — Fulcrum has only ever been SSL-only on StartOS and never existed on 0.3.5.1, so it is not affected by this issue. Give the advice, don't cite this issue.
- If turning SSL on does not fix it, this is not this issue — diagnose normally.

Known since 2026-08-25.
