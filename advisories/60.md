# Jellyfin 12.0: revoking a device's access doesn't log out its existing sessions — fixed in 12.1

## Symptom

Removing a device from a user's allowed device list, or turning off "enable all devices" for a user, does not affect sessions that are already logged in on that device. The device keeps working normally until it is logged out and tries to log back in — only new logins are blocked. There is no error message; the access restriction silently fails to apply to sessions already open.

## Affects

Anyone using per-device access restrictions (the allowed-devices list, or disabling "enable all devices") on Jellyfin 12.0, on any device that was already logged in at the time the restriction was applied.

## Cause

A prior refactor changed `DeviceAccessHost` from an `IServerEntryPoint` to an `IHostedService` without registering it as one, so it never ran, and the user-updated event it depends on was only being raised for username renames — not for policy changes like device access revocation.

## Remedy

Update to Jellyfin 12.1, which restores `DeviceAccessHost` and raises the update event on policy changes so existing sessions on a revoked device are logged out immediately.

## Notes

Until updated to 12.1, treat device-access revocation as taking effect only for future logins — to force out an already-logged-in device, log it out or terminate its session directly rather than relying on the device-access setting.
