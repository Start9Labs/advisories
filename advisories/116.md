# Open WebUI: importing a chat export unarchives every chat and drops chat variables

## Symptom

After exporting chats (Settings → Data Controls → Export Chats), deleting all chats, and importing the export back in, every chat — including ones that were archived when exported — appears in the main chat list, and Archived Chats is empty. Chat variables also come back empty. Tags, folder and timestamps are restored correctly.

## Affects

Anyone who uses Export Chats / Delete All Chats / Import Chats as a way to back up or reorganize their chats and had archived chats or chat variables at the time of export. Tags, folders and timestamps are unaffected. Not tied to a particular model or Ollama version.

## Cause

The chat import form has no field for archived state, so imported chats fall back to the "not archived" default; it also never sends the chat variables field to the import endpoint, even though the export file records both.

## Remedy

No fix has shipped yet. If you rely on export/import to preserve your chat organization, note which chats are archived and re-archive them by hand after importing, and expect to re-enter any chat variables — the import will not restore either automatically.

## Do not

- Do not delete all chats before importing an export as a way to "clean up" — this is the only way back, and it does not restore the archive shelf or chat variables.

## Notes

Reported by an Open WebUI collaborator and confirmed (labeled `bug`, `confirmed issue`). A related report, tracked separately upstream as #30150, covers the same import losing pinned state.
