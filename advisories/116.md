# Open WebUI: importing a chat export unarchives every chat and drops chat variables

## Symptom

After exporting chats (Settings → Data Controls → Export Chats), deleting all chats, and importing the export back in, every chat — including ones that were archived when exported — appears in the main chat list, and Archived Chats is empty. Chat variables also come back empty. Tags, folder and timestamps are restored correctly.

## Affects

Anyone who uses Export Chats / Delete All Chats / Import Chats as a way to back up or reorganize their chats and had archived chats or chat variables at the time of export. Tags, folders and timestamps are unaffected. Not tied to a particular model or Ollama version.

## Cause

The chat import form has no field for archived state, so imported chats fall back to the "not archived" default; it also never sends the chat variables field to the import endpoint, even though the export file records both.

## Remedy

Fixed upstream by #30155, which restores both the archived state and chat variables on import. Update to a version of Open WebUI that includes this fix. If running an older version, note which chats are archived and re-archive them by hand after importing, and expect to re-enter any chat variables.

## Do not

- Do not delete all chats before importing an export as a way to "clean up" on a version without this fix — this is the only way back, and it will not restore the archive shelf or chat variables.

## Notes

Reported by an Open WebUI collaborator and confirmed (labeled `bug`, `confirmed issue`). A related report, tracked separately upstream as #30150, covers the same import losing pinned state; that issue was fixed separately by #30151. Note (unconfirmed): the export also carries a `share_id` field that import still ignores, per the #30151 author — restoring it would hand a new chat an old share link, so this appears to be left alone intentionally rather than a bug.
