# Jellyfin: upgrade to 12.1 hangs forever on migration "ChangeOwnerIdToGuid" pinning one CPU core, especially with large libraries

## Symptom

After updating to Jellyfin 12.1, the server never finishes starting. The log stops after:

```
[INF] InternalDatabaseMigration: Perform migration 20260113203012_ChangeOwnerIdToGuid
```

and repeats indefinitely:

```
[WRN] ... Health check StartupCheck with status Degraded completed with message 'Server is still starting up.'
```

No error or success message ever appears for this migration. One CPU core (a single .NET ThreadPool worker) sits near 100% the entire time, with heavy logical disk reads but little physical I/O. Restarting the container starts the same migration over from the beginning with the same result. This is most noticeable on libraries with very large databases (reports involve databases in the multi-GB range with hundreds of thousands of items), but has also been reported on smaller/bare-metal installs.

## Affects

Anyone updating Jellyfin to 12.1 whose database has not yet run the `ChangeOwnerIdToGuid` migration — i.e. anyone updating from 10.11.x. Larger libraries are hit harder and may appear to hang for hours, but multiple reporters with ordinary libraries hit the same stall.

## Cause

Not confirmed. Reported as pathological O(n²)-like behavior in the migration doing repeated full scans of the database rather than a single pass; a maintainer has referenced a pull request that may fix it, but no fix has merged yet.

## Remedy

There is no fix yet — no Jellyfin release resolves this. If an update to 12.1 is stuck on the `ChangeOwnerIdToGuid` migration, do not force another restart, since it restarts the same migration from the beginning and wastes the time already spent; either let it continue running or restore the pre-upgrade backup Jellyfin makes automatically before the migration starts, and hold off on updating to 12.1 until a fix ships.

## Do not

- Repeatedly stop/restart the container hoping it will progress further — it restarts the migration from scratch each time.

## Notes

Unconfirmed: whether database size is the actual trigger, or just what makes the stall visible; some reporters have unremarkable libraries and hit it too. Watch jellyfin/jellyfin for a merged fix and update this advisory with the version once one ships.
