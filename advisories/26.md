# Jellyfin: playlists with accented filenames scan with no songs inside — fixed in 12.1

## Symptom

After scanning the library, a playlist that targets files or folders whose names contain accented characters shows up empty ("Playlist has no songs inside").

## Affects

Jellyfin users with playlists pointing at media whose file or folder names contain accented characters (e.g. non-ASCII Latin letters).

## Cause

`.m3u` playlists have no declared text encoding. `PlaylistItemsProvider.GetFromStream(stream)` decoded them as UTF-8, but playlists written by Windows media players in the local codepage turned accented characters into `U+FFFD`, causing `File.Exists` to fail and the entry to be silently dropped. Separately, accented characters can be encoded precomposed (NFC) or decomposed (NFD), so a playlist written on a platform preferring the other form never matched byte-for-byte.

## Remedy

This is fixed in Jellyfin 12.1, which charset-sniffs plain-text playlist formats instead of assuming UTF-8. Update to that version and re-scan the library.

## Notes

Reported on server version 10.11.11; the fix (PR #17930) was merged and confirmed by a maintainer to land in 12.1.
