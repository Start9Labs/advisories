# Jellyfin update from 10.11.11 to 12.0 fails with "SQLite Error 19: 'FOREIGN KEY constraint failed'" — fixed in 12.1

## Symptom

After updating from 10.11.11 to 12.0, Jellyfin fails to start. The log shows the migration `FixIncorrectOwnerIdRelationships` running, finding duplicate database entries, and then failing:

```
[FTL] InternalCodeMigration: Error: SQLite Error 19: 'FOREIGN KEY constraint failed'.
[ERR] InternalCodeMigration: Migration 20260115120000_FixIncorrectOwnerIdRelationships failed
```

The server does not come up after this.

## Affects

Anyone updating Jellyfin from 10.11.11 directly to 12.0 whose library has duplicate database entries that the migration tries to clean up. Reported both with and without third-party plugins installed, so it is not limited to a particular plugin set.

## Cause

The `FixIncorrectOwnerIdRelationships` migration in 12.0 deletes duplicate item entries but does not handle existing foreign key references to those entries first, so the delete violates a foreign key constraint and the migration — and startup — fails.

## Remedy

Update to Jellyfin 12.1, which contains the fix for this migration.

## Notes

Rolling back to the pre-update backup restores service with no data loss while waiting to update to 12.1.
