# Home Assistant: Tuya switches fail with "sign invalid" (-9999999) or hang for minutes — disable IPv6

## Symptom

Tuya integration write commands (`switch.turn_on`/`switch.turn_off`) intermittently fail with `network error:(-9999999) sign invalid`, or take one to several minutes to complete instead of responding instantly. State reading via MQTT keeps working normally throughout, which makes this look like an authentication problem rather than a network one. Tuya integration setup or QR-code re-authentication can also hang for minutes before failing. `continue_on_error: true` on the failing action does not reliably let the automation proceed.

## Affects

Home Assistant installs with IPv6 enabled that use the official Tuya cloud integration. Reported on Home Assistant Container, Home Assistant OS (including Home Assistant Green), and Home Assistant OS running as a VM. Devices controlled locally instead (e.g. via a local/LAN-based Tuya integration) are not affected.

## Cause

Tuya's cloud API hosts (`apigw.tuyaeu.com`, `apigw.iotbing.com`) resolve to IPv6 addresses that are unreachable from many networks. The connection attempt hangs on IPv6 until it times out before falling back to IPv4, and the resulting timeout is surfaced by the Tuya integration as the generic `-9999999 sign invalid` error rather than a connection/timeout error.

## Remedy

Disable IPv6 in the network settings. This restores instant, reliable responses for Tuya cloud commands. There is no fix yet in the Tuya integration itself for the underlying slow IPv6-to-IPv4 fallback.

## Do not

- Don't troubleshoot this as a Tuya account, credentials, or authentication problem — the "sign invalid" message is misleading; the underlying issue is a network timeout.

## Notes

Disabling IPv6 system-wide will also affect other integrations that depend on it (for example Matter/Thread setups) — this is a real tradeoff for those users, not a side effect to gloss over. No IPv6-safe workaround is confirmed for Home Assistant OS; the alternative of adding an IPv4-preference rule to `/etc/gai.conf` has only been confirmed for Container installs with host networking, and is not a practical option on Home Assistant OS.
