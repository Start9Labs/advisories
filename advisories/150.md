# Immich: editing an album's description while files are uploading silently drops the change

## Symptom

While uploading photos or videos into an album, opening the album's edit dialog and typing a description (or renaming it) and saving appears to work, but the description reverts to blank once the upload finishes. There is no error shown.

## Affects

Anyone who edits an album's title or description while an upload of new assets into that same album is still in progress. Editing the description before starting an upload, or after it has fully finished, is not affected.

## Cause

A race condition in the web client: when the upload completes, the handler for the newly-added assets re-fetches the whole album from the server to update the count. If that fetch lands before the description save has committed, it overwrites the just-saved description with the server's stale (null) value.

## Remedy

This is fixed upstream (immich-app/immich#31758) by no longer re-fetching the whole album on upload completion. The fix has not yet reached a released Immich version — it will be available once a StartOS Immich package build containing it is published. Until then, avoid editing an album's description while an upload into that album is still running; wait for the upload to finish first.

## Notes

If a description was already dropped this way, it was never saved server-side — there is no data to repair, just re-enter and save the description once no upload is in progress.
