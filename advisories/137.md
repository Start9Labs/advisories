# Open WebUI: leaving the chat while Voice Mode is active leaves the microphone recording in the background

## Symptom

Voice mode is used in a chat, then the user navigates away to another page (Admin Panel, Workspace, Notes). The microphone keeps recording and transcribing after leaving — speech from other pages gets transcribed and sent as prompts to the chat that is no longer open. Returning to the chat and reopening voice mode can leave an extra microphone stream running as well.

## Affects

Anyone who uses Voice Mode in a chat and then navigates to a different page in Open WebUI without explicitly ending the voice call first.

## Cause

The voice mode flag stays set when the chat page unmounts, so the voice overlay's teardown restarts recording on the already-destroyed component instead of shutting it down, keeping the microphone stream open.

## Remedy

This is fixed upstream, but the fix has not shipped in an Open WebUI release yet — there is no release since the merge. Once a release containing it reaches StartOS, leaving the chat page will fully shut down the microphone. Until then, explicitly end the voice call (rather than just navigating away) before leaving the chat, and check that the browser's microphone indicator is off if you're unsure.

## Do not

- Don't assume closing the browser tab or muting is required — ending the voice call before navigating away is sufficient to stop the recording today.

## Notes

Verified by the author with a fake microphone in Chromium: after the fix, moving to another page (e.g. Workspace) drops the live transcription requests and microphone tracks to zero, whereas before the fix they persisted.
