# Element Web: editing a message re-escapes plain text, adding stray backslashes (e.g. `_light.scss` becomes `\_light.scss`)

## Symptom

Pressing the up arrow (or otherwise opening a plain-text message for editing) shows the message with extra backslashes inserted before characters like underscores — for example a message reading `path/to/_light.scss` reopens as `path/to/\_light.scss`. If the edit is saved, the sent message now actually contains the backslash the sender never typed. The same message can also show as "modified" (Save becomes enabled) even though nothing was changed.

## Affects

Anyone editing a previously sent plain-text message that contains a character markdown treats specially (underscore, asterisk, backslash, backtick, etc.), even though the message was never sent as markdown. Messages originally sent with rich formatting are not affected — the HTML path is unchanged.

## Cause

The edit composer re-escaped every markdown-special character in the message body regardless of whether the text would ever be parsed as markdown, instead of only escaping when the body actually needed it.

## Remedy

This is fixed upstream in Element Web. The fix has merged but has not yet reached a released version — none has been published since the merge. Tell the customer the problem is known and fixed, and it will be available once a release containing the fix reaches StartOS.

## Notes

The currently available StartOS package (1.12.27.3:0) does not contain this fix.
