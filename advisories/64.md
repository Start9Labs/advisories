# Gitea: OIDC/Entra ID sign-in resolves to an organization or 404s after a stale linked account was removed — fixed in 1.26.3

## Symptom

A user signing in via OIDC (including Entra ID) is signed in as an organization instead of their own account, or sign-in fails with a 404 after that previously-linked organization or user account was deleted.

## Affects

Instances using OIDC/OAuth2 external login where the external account was, at some point, linked to a user that was later deleted or turned into/replaced by an organization. Most OIDC users, whose linked account is unchanged, are unaffected.

## Cause

Gitea's stored external-login link could point to an organization or a deleted user; on sign-in, Gitea kept resolving to that stale link instead of validating it.

## Remedy

Update to Gitea 1.26.3. The fix validates the resolved user during OAuth2/OIDC login, discards stale links to deleted or non-individual accounts, and lets the external account relink correctly on the next sign-in.
