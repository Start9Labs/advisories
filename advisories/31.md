# Jellyfin 12.0: CBZ comic libraries flood the log with `JsonException: The input does not contain any JSON tokens.` — fixed in 12.1

## Symptom

Scanning or refreshing metadata on a CBZ comic/manga library logs an Error-level stack trace for every affected file:

```
[ERR] MediaBrowser.Providers.Books.ComicBookInfo.ComicBookInfoProvider: failed to load ComicBookInfo metadata: "/data/manga/.../file.cbz"
System.Text.Json.JsonException: The input does not contain any JSON tokens. Expected the input to start with a valid JSON token, when isFinalBlock is true. Path: $ | LineNumber: 0 | BytePositionInLine: 0.
```

On a large library this can be tens of thousands of errors, dominating the daily log. Metadata itself (e.g. from ComicInfo.xml) is unaffected.

## Affects

Jellyfin 12.0.0 with a book/comic library using the built-in Comic Provider, where CBZ files have an empty (not missing) ZIP archive comment — a typical case for CBZs produced by tools like Suwayomi.

## Cause

`ComicBookInfoProvider` only treats a `null` ZIP comment as "no ComicBookInfo metadata." An empty string comment (`""`) is not null, so it is passed to JSON deserialization, which throws, and the exception is logged at Error for every such file.

## Remedy

Fixed in Jellyfin 12.1.

## Notes

The underlying library and metadata are unaffected — this is log noise, not a data-loss or missing-content issue.
