# Service Web UI unreachable after an update — "Secure Connection Failed / PR_END_OF_FILE_ERROR" — rebuild the container

## Symptom

After updating a service, its Web UI becomes unreachable on every address and stays that way. The browser shows:

```
Secure Connection Failed
The page you are trying to view cannot be shown because the authenticity of the received data could not be verified.
Error Code: PR_END_OF_FILE_ERROR
```

The service's own logs show nothing wrong — the service itself is fine. The OS journal repeats an error for every connection attempt:

```
DEBUG start_core::error: ... Network Error:
  0: 10.0.[redacted]:80: Host is unreachable (os error 113)
  1: Host is unreachable (os error 113)
```

## Affects

Any service, after an update recreates its container. This is not tied to a particular package or payload — it is a property of the update/recreate cycle itself, and can in principle happen on any update. Reported against Nextcloud on StartOS 0.4.0.

## Cause

StartOS's reverse proxy keeps a routing entry for the service pointing at the container's old internal IP. A container gets a new IP on every recreate, and under a lifecycle race the old routing entry is never released, so it sits in front of the new one with no fallthrough — every connection is routed to an address nothing answers, and the interface is permanently black-holed until the container is rebuilt.

## Remedy

Rebuild the affected service's container to restore access immediately.

A fix bounding the shutdown path that causes this has been approved and merged; it ships in 0.4.0.2.

## Do not

- Do not treat this as a certificate problem — the TLS error is a side effect of the backend connection failing, not an actual certificate issue.
- Do not look in the service's own logs for a cause — the service is never in the path for this failure.

## Notes

Report any recurrence with `start-cli net vhost dump-table` output captured before rebuilding, since rebuilding destroys the evidence needed to confirm the trigger.
