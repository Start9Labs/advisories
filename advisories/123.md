# Open WebUI: a code block that prints output and then errors shows only the printed output, hiding the failure

## Symptom

Running a code block (code execution on, e.g. the Pyodide engine) that prints something and then raises an error shows only the printed output — no error, no result — making a run that actually failed look like it succeeded.

## Affects

Anyone using code execution (on by default) with a script that prints before it fails. A script that fails without printing anything first still shows the error correctly, which is why this is easy to miss.

## Cause

The result panel only rendered `stdout` or `stderr`, never both — so when the sandbox returned both a printed line and an error, the error was dropped.

## Remedy

Fixed upstream (open-webui/open-webui#30286, merged into `dev`), but not yet in a released version — the latest available is 0.11.3:1. There is no released version yet that carries this fix; until then, treat a code block that only shows printed output with no result as unverified and check its logic manually rather than trusting that it succeeded.

## Notes

Fix is on `dev`, unreleased as of 0.11.3:1. No target version has been named yet for when it ships.
