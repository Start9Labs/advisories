# Open WebUI: copying the JWT token or API key in Settings > Account also saves the form

## Symptom

In Settings → Account, clicking the copy icon next to the JWT token or the API key copies the value, but also saves the whole account form — a "Settings saved successfully!" message appears, and any unsaved edits to the profile (for example a changed Name) get saved along with it. If the Name field is empty, clicking the copy icon shows the browser's required-field warning instead of just copying.

## Affects

Anyone using the copy buttons for the JWT token or API key on the Account tab in Settings while the form has unsaved changes. Using the tab's own Save button is unaffected; copying with no pending edits copies normally but still silently saves the (unchanged) form.

## Cause

The copy icons are buttons with no explicit `type` attribute, so browsers treat them as submit buttons for the account settings form.

## Remedy

This is fixed upstream — the copy icons no longer submit the form — but the fix has not shipped in an Open WebUI release yet. It will be available once a StartOS Open WebUI release containing it is published. Until then, save or discard any intended profile edits deliberately before using the copy icons, and re-check the Name field if you see a required-field warning after copying.

## Notes

Fix merged upstream (open-webui/open-webui#30956, closing #30955); no release has been made since the merge.
